# AutoPlanner — Project Setup Changes

## Overview
Full-stack project scaffolded from the design diagrams (`classDiagram.md`, `erDiagram.md`, `sequenceDiagram.md`, `useCaseDiagram.md`, `idea.md`).

**Stack:** Node.js + Express + Prisma (SQLite) for the backend, React + Vite + Tailwind CSS for the frontend.

### Services (`/backend/src/services`)
| File | Description |
|------|-------------|
| `schedulerService.js` | Core scheduling engine using a **Greedy Constraint-Satisfaction** algorithm. Builds a work list of `(ClassGroup × Subject × hoursPerWeek)` entries, then iterates `TimeSlot → Teacher → Room` combinations and assigns the first combination that passes all constraints. Returns count of assigned vs. unassigned entries. |
| `constraintValidator.js` | Validates individual constraints: teacher availability window, room capacity vs. student count, and conflict checks (teacher/room/class double-booking at the same time slot) |

## Algorithm

The scheduler in `schedulerService.js` uses a **Greedy Constraint-Satisfaction** approach:

1. Build work list: `ClassGroup × Subject` repeated `hoursPerWeek` times.
2. For each entry, iterate `TimeSlot → Teacher → Room` and pick the first valid combination.
3. Constraints checked per assignment: teacher availability, teacher conflict, room capacity, room conflict, class conflict.
4. Valid plan is bulk-saved; unresolved entries are reported back to the client.
